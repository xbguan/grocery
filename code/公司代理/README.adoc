= 公司代理（macOS 菜单栏 App）
:author: xbguan
:date: 2026-10-23
:doctype: article
:toc: left
:toclevels: 3
:icons: font

菜单栏常驻的小工具：把 macOS 系统代理和 Codex CLI 一起切到公司 3proxy，内置本地免认证中继解决浏览器代理认证弹框。纯 Swift 实现，除 Xcode Command Line Tools 外无第三方依赖。

== 目录结构

[cols="2,3",options="header"]
|===
|路径 |说明
|`Sources/Config.swift` |配置读写（`~/.config/corp-proxy/config`，键值格式，权限 600）、VPN 模式枚举
|`Sources/ProxyController.swift` |调 `networksetup` / `scutil` 挂载系统代理、改写 `~/.codex/.env`
|`Sources/RelayServer.swift` |本地免认证中继，监听 `127.0.0.1:7899`，自动注入 `Proxy-Authorization`
|`Sources/SettingsWindow.swift` |设置窗口（代理地址/端口/账号/密码、VPN 方式、中继端口、直连白名单）
|`Sources/LoginItem.swift` |开机自启（`SMAppService`）
|`Sources/Uninstaller.swift` |卸载清理
|`Sources/AppDelegate.swift` |菜单栏菜单、状态刷新、开关流程
|`Sources/main.swift` |入口（启动时按配置决定 `regular`（有 Dock 图标）/ `accessory`（仅菜单栏））
|`IconGen.swift` |用 Cocoa 画图生成 AppIcon.iconset
|`build.sh` |一键编译 + 组装 .app + ad-hoc 签名 + 生成 DMG
|`packaging/卸载公司代理.command` |App 已被拖进废纸篓时的备用清理脚本（随 DMG 分发）
|`dist/公司代理-2.0.5.dmg` |成品安装包
|===

== 构建

[source,bash]
----
cd code/公司代理
./build.sh
# 产物：build/app/公司代理.app、dist/公司代理-2.0.5.dmg
----

要求：macOS 13+、Xcode Command Line Tools（`swiftc`）。

产物为**通用二进制**（universal2），同时包含 `arm64` 与 `x86_64`：

* `arm64` —— Apple Silicon（M1/M2/M3/M4 及后续）原生运行，不需要 Rosetta
* `x86_64` —— Intel Mac 原生运行

脚本对两个架构分别执行 `swiftc -target <arch>-apple-macos13.0`，再用 `lipo -create` 合并，
因此在 Intel 或 Apple Silicon 任一机器上构建，都能产出两边通用的包。若某个架构编译失败
（例如精简过的 SDK 缺少对应 slice），脚本会打印警告并降级为单架构，不会中断。

签名方式为 ad-hoc（`codesign --sign -`），换机器分发时对方首次打开需右键 →「打开」越过 Gatekeeper。

== 安装

打开 DMG，把 `公司代理.app` 拖进 `Applications`。启动后常驻菜单栏；需要在程序坞也放一个图标时，勾选菜单里的「在程序坞显示」（或「设置…→ 外观」），勾选后可将图标拖到程序坞固定。

勾选「在程序坞显示」之后：

* *单击程序坞图标*：弹出与顶部菜单栏图标完全相同的菜单（不会直接打开设置窗口）
* *右键程序坞图标*：系统快捷菜单，可一键启用 / 关闭代理
* *改配置*：点菜单里的「设置…」（快捷键 `⌘,`）

菜单里的状态一律用 SF Symbol 图标表达：绿色实心圆=已接通、空心圆=已关闭、橙色三角=状态异常；信息行的「中继」「自启」也用闪电 / 电源图标标出通断，不再使用 ✓ ✗ 字符。

== 配置项

配置文件：`~/.config/corp-proxy/config`（600）。App 的「设置…」写的就是它，也可手改，App 5 秒内自动重载。

[cols="2,1,3",options="header"]
|===
|键 |示例 |说明
|`CORP_HOST` |`172.17.2.15` |公司 3proxy 地址
|`CORP_PORT` |`7887` |3proxy HTTP 端口
|`CORP_USER` |`admin` |代理用户名
|`CORP_PASS` |`******` |代理密码
|`RELAY_PORT` |`7899` |本地中继端口（系统代理指向 `127.0.0.1:该端口`）
|`VPN_MODE` |`auto` |`auto` / `hdvpn` / `l2tp`，见下
|`BYPASS` |`*.hd123.com gitlab.hd123.com` |直连白名单（空格分隔）
|`SHOW_IN_DOCK` |`1` |是否在程序坞显示图标：`1` 显示 / `0` 仅菜单栏
|===

=== VPN 接入方式

[cols="1,3",options="header"]
|===
|模式 |行为
|`auto` |检测到 `ppp0` 有地址 → 按 HD-VPN；否则按路由器 L2TP
|`hdvpn` |系统代理同时挂到「VPN」服务 + Wi-Fi/Ethernet/USB LAN
|`l2tp` |只挂物理网卡，不给「VPN」服务设代理
|===

=== 程序坞显示

默认只驻留菜单栏（`LSUIElement=false` + 启动时 `setActivationPolicy(.accessory)`，不占程序坞）。

需要常驻程序坞时，勾选菜单栏菜单里的「在程序坞显示」，或「设置…→ 外观 → 在程序坞显示图标」：

* 立即切换激活策略为 `.regular`，Dock 图标出现，可拖到程序坞固定
* 同时装上一套最简主菜单（关于 / 设置 / 代理 / 窗口），⌘, ⌘Q ⌘M 可用
* 右键 Dock 图标可直接「启用 / 关闭 / 重新应用」代理或打开设置
* 点 Dock 图标且当前无窗口时，自动打开设置窗口
* 关闭选项则回到 `.accessory`，Dock 图标消失、菜单栏图标保留

== 工作原理

. 用户点「启用」→ `ProxyController` 给多个网络服务设置 HTTP/HTTPS 代理 `127.0.0.1:7899`
. 中继收到请求后与 `CORP_HOST:CORP_PORT` 建连，注入 `Proxy-Authorization: Basic ...` 再转发
. 同时把 `HTTP_PROXY/HTTPS_PROXY/ALL_PROXY` 写入 `~/.codex/.env`（Codex CLI 只认环境变量，不读系统代理）
. 「关闭」则清空各网络服务代理、把 `.env` 改回直连

=== 两条硬规则（2.0.2 起）

**永远经本地中继，不再回退到直连公司上游。** 直连时系统代理里存的账号密码 Chromium 不读，页面必然弹「输入代理用户名和密码」。中继没起来就报错，不改系统代理。

**账号或密码为空时拒绝启用。** 公司 3proxy 空凭据回 407，浏览器同样会弹认证框。点「启用」会先弹提示，可「去设置…」，也可明确选「仍然启用」（适用于确实无需认证的代理）。

=== 启动自检

每次启动 1.5 秒后检查一次系统代理，只处理「指向本机中继或公司上游」的设置，其它代理（如 Clash）不碰：

[cols="1,2",options="header"]
|===
|发现的状态 |处理
|没填账号密码，却挂着代理 |直接关闭系统代理，菜单显示「已关闭遗留的系统代理」
|指向公司上游（直连，会弹认证框） |自动改挂到 `127.0.0.1:<中继端口>`
|指向中继且配置正常 |不动
|===

首次启动（还没有配置文件）时，如果系统里残留着上次的代理，也会被按上面规则清理，不会出现「装上就弹认证框」。

=== 退出 / 关机时的清理

代理指向的是本机中继，App 一退出中继就没了；若代理设置留着，整台机器会立刻断网。
所以每条退出路径都会先撤代理、再停中继：

[cols="1,2",options="header"]
|===
|退出方式 |触发点
|菜单「退出」、⌘Q、程序坞右键「退出」、AppleScript quit |`applicationShouldTerminate`
|关机、重启、注销 |`NSWorkspace.willPowerOff` 通知（提前清理）+ 随后的 terminate
|`kill` / `killall`、系统关机超时的强制终止、Ctrl-C |SIGTERM / SIGINT / SIGHUP 信号源
|===

清理**只撤自己写的**：逐个网络服务比对代理地址，是 `127.0.0.1:<中继端口>` 或公司上游才关，
Clash 等其它代理原样保留。这里刻意不看 `scutil` 的全局代理状态 —— 主服务是 ppp0/VPN 时
全局状态反映不到物理网卡上的设置，会导致漏清。

行为可以在菜单里用「退出时关闭代理」开关（默认开）关掉；关闭后退出只停中继、保留代理设置。

=== 为什么需要本地中继

macOS 系统代理里保存的代理账号密码，Chromium 系（Chrome/Edge/ChatGPT 桌面版）不读取，会反复弹「登录以访问此站点」。中继在本机代填认证，浏览器看到的是无需认证的 `127.0.0.1:7899`。

=== 中继的两个实现要点（踩坑记录）

* 双向数据搬运用**每条连接两个专用 `Thread`**，不能放 `DispatchQueue.global()`：GCD 全局池只有 64 线程，浏览器几十条常驻 CONNECT 隧道会把池子占满，新请求排队 → 表现为「网页和 CLI 一起变慢」。
* 连接超时用 `poll()` 而非 `FD_SET/FD_ZERO`（`swiftc` 下这些宏不可用）。

== 卸载

菜单栏 →「卸载公司代理…」：关系统代理、`.env` 改回直连、停中继、注销开机自启、删除配置/日志/偏好/缓存/LaunchAgent，最后自删 App 本体。可选是否连带删除旧版命令行脚本 `~/.local/bin/corp-proxy`。

App 若已进废纸篓，双击 DMG 里的 `卸载公司代理.command` 做同样清理。

== 已知限制

* 公司出口对 `api.openai.com` 会做 TLS reset（30 次里约 18 次失败）；`chatgpt.com/backend-api` 稳定可用，Codex 走后者，不受影响。
* 开启系统代理后，iCloud/微信等流量也会经过公司 3proxy，会落在对方 `log D` 日志里。
* 不能与 TUN 模式代理同时使用（会与公司 VPN 抢路由）。
* 被 **SIGKILL** 杀掉（强制退出、崩溃、关机超时被硬杀）时没有机会执行清理，系统代理会残留成
  「指向已停止的中继」→ 表现为全部网络不通。重新打开 App 即可自动修正（见「启动自检」）；
  也可手动执行 `networksetup -setwebproxystate Wi-Fi off` 应急。
